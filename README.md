# 基于人脸识别的社保身份认证系统

《信息系统应用开发》课题二十二。

使用 C#、Windows Forms、.NET Framework 4.5.2、SQL Server 和课堂 `FacePlatformCtrl.BioFPCtrl`。基于课程任务书实现登记、认证、记录与统计，并按最新要求简化为单管理员使用。

当前版本：**v1.0.8**。保留现有唯一管理员登录，移除管理员账户维护、密码修改与权限设置页面及接口，并将多角色权限框架简化为统一的登录与账号存在校验。同一社保编号只保留首次成功领取记录，支持连续注册多人、删除已有领取记录的成员，以及经确认清空全部领取记录。操作日志仅记录注册人员、删除人员、清空认证领取记录三类成功操作。四个窗体均使用标准 WinForms 设计器结构。

## 克隆与开发环境

```powershell
git clone https://github.com/yz-0609/Class_SocialSecurityAuth.git
cd Class_SocialSecurityAuth
```

- Windows、Visual Studio 2015（本机验证版本为 Community Update 3），安装 .NET Framework 4.5.2 开发组件。
- SQL Server 数据库引擎（本机使用 SQL Server 2022 Developer 默认实例），SSMS 用于查看和管理数据库。仅安装 SSMS 不会提供数据库引擎。
- 可用摄像头及课堂人脸 SDK 的 x86 运行依赖。

仓库包含构建所需的 SDK 托管程序集、原生 DLL、提示音、数据库脚本、源码和项目文档，不依赖 NuGet 还原。编译结果、VS 缓存、本地数据库、日志和压缩包不提交；克隆后需先生成程序。

## 打开与运行

1. 在 VS2015 中打开 `Source/SocialSecurityAuth.sln`，启动项目选择 `SocialSecurityAuth`。
2. 选择 `Release | x86` 或 `Debug | x86`，生成后运行。
3. 生成的可执行程序位于 `Build/Release/SocialSecurityAuth.exe`。使用 Release 生成后也可双击根目录的 `启动系统.cmd`；该脚本不会自动编译。
4. 程序启动先展示编写人和课题信息 2 秒，然后连接数据库、加载 SDK 并进入识别主界面。

新数据库的初始管理登录：**账号 `admin`，密码 `Admin@123`**。已有数据库继续使用原来的管理员和密码，升级不会重置。当前程序不提供管理员新增、删除、信息修改、密码修改或权限设置入口。

也可在项目根目录使用 PowerShell 编译并运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Build.ps1 -Configuration Release
.\Build\Release\SocialSecurityAuth.exe
```

`Build.ps1` 使用 VS2015 默认安装位置的 MSBuild 14.0；如安装位置不同，修改脚本中的 `$buildTool` 路径。必须选择 x86，不能使用 Any CPU 或 x64。

首次运行会执行 `Database/00_CreateDatabase.sql`，创建独立数据库 `SocialSecurityAuth`、六张表和两个初始单位，再生成默认管理员的密码盐与散列。初始化可重复执行，已有人员、人脸与密码保留；版本升级按下文规则整理领取记录。原有课堂数据库 `myspl` 不作修改。程序不会自动添加社保人员、人脸或认证记录。

如果当前 Windows 账户没有创建数据库权限，可先在 SSMS 中使用有权限的账户执行建库脚本，再为运行账户授予相应访问权限。

## 实际操作顺序

1. 点击主界面的“管理”，输入管理账号和密码。
2. 在“人员登记与管理”输入社保编号、姓名、性别及所属单位。所属单位可选择，也可直接输入新名称。
3. 点击“采集并注册”，正对摄像头等待 SDK 返回注册结果。新人员的信息与人脸模板会在同一事务中保存。注册成功后表单自动清空，可直接填写下一位人员的信息。也可以先“保存修改”登记基本资料，继续为该人员采集人脸。
4. 选中表格中的已有人员时进入修改状态，社保编号锁定；登记另一位请点击“新增”。完成登记后返回识别主界面，系统自动重新加载全部模板并连续识别。首次通过保存一条领取记录；再次通过仍显示认证成功和“已领取”，不再新增记录。失败时仅提示并更新已知人员的当前认证状态。
5. 管理界面包含“人员登记与管理”“认证领取记录”“数据统计”“操作记录”四页，可查看首次领取记录、按单位查询四类名单及查看操作记录。“认证领取记录”页的“清空认证领取记录”按钮经确认后清空所有单位的记录，重置当前认证状态，保留人员与人脸；下次成功可重新登记领取。

人员即使已有认证领取记录也可以删除。删除会移除档案及人脸模板，历史记录保留删除时的姓名、社保编号和单位，仍可按单位查询。再次使用同一社保编号登记，不会重复登记领取。管理员表、原账户和历史操作日志继续保留，不进行删表或清空。

## 人脸识别实现

沿用 [老师的 DoorAccess2026](https://github.com/yz-0609/DoorAccess2026) 方法：

- `ModuleLoad()` 加载模块，`ModuleUnload()` 释放模块。
- `Enroll()` 发起采集，`EnrollNotify` 接收特征模板。
- `GetFaceCodeLen()` 校验模板长度，`SetFaceCode()` 批量加载模板与索引。
- `Identify()` 发起识别，`IdentifyNotify` 将 SDK 索引映射回人员编号。
- `Cancel()` 停止当前操作；连续识别回调采用课堂两秒节流。

全程序共用一个控件，在主界面与管理界面之间卸载、移动并重新加载，避免两个模块争用摄像头。回调切换时校验状态，取消后到达的旧结果不会写入数据库。设备状态通过 SDK `StatusNotify` 接收，设备移除或打开异常时提示重新连接。

SDK DLL 来自本机课堂 demo。`Source/SocialSecurityAuth/Lib` 保存两个托管程序集；`Runtime` 保存原生 DLL 和必要音频。生成时自动复制到输出目录，不需要 NuGet。SDK 的原生部分是 32 位，因此必须使用 x86。

## 记录与统计口径

- 同一社保编号只在首次识别通过时保存一条领取记录和领取时间。后续成功不新增记录、不改首次领取时间。
- 领取去重由数据库唯一索引和事务共同保证，并发识别也只能产生一条领取登记。删除成员后领取凭据仍保留，同一社保编号再次登记也不会重复领取。
- 认证失败不保存领取记录；已知人员的最新认证时间和结果保存在人员表供统计使用。未知人员失败只提示，不归入具体人员或单位。
- 已采集人员按是否存在模板查询；已通过、未通过、未认证名单按人员表保存的最新认证状态查询，与首次领取记录分开。
- 清空须登录现有管理员，数据层确认账号仍存在，同时写入操作日志。无论当前筛选哪个单位，清空范围均为全部记录；清空后所有现存人员恢复未认证状态，可重新首次领取。
- 已采集状态与认证状态可以交叉，四类人数不相加作为总人数。界面汇总和明细来自同一次人员快照。
- 未设置认证周期、待遇金额、真实打款、独立资格状态管理、导出或多终端功能。

## 目录与主要代码

```text
Source/
  SocialSecurityAuth.sln
  SocialSecurityAuth/
    MainForm.cs / MainForm.Designer.cs  识别主窗口
    ManageForm.cs / ManageForm.Designer.cs  管理窗口及页签
    FaceService.cs                      课堂 SDK 接入和生命周期
    AppRepository.cs                    数据访问、登录校验与业务事务
    Database.cs                         首次初始化
    PasswordHasher.cs                   加盐 PBKDF2 密码散列
    SplashForm.cs / LoginForm.cs          启动展示与管理登录
    App.config                          数据库连接和编写人信息
    Lib/                                SDK 托管程序集
  SocialSecurityAuth.Tests/              独立集成测试与界面检查入口
Database/00_CreateDatabase.sql           可重复执行的建库建表脚本
Runtime/                                x86 原生 DLL 和 Sound 音频
Build/Release/                          本地生成的程序及依赖，不提交 Git
```

四个顶层窗体是 `SplashForm`（启动页）、`LoginForm`（登录框）、`MainForm`（识别主界面）和 `ManageForm`（管理员界面）。每个窗体有对应的 `.cs`、`.Designer.cs` 和 `.resx` 文件，可在 VS2015 中右键主 `.cs` 文件选择“查看设计器”。管理员界面的人员、领取记录、统计和日志是同一个窗体的四个页签。

布局保存在 `.Designer.cs`，业务逻辑和事件处理保存在主 `.cs`。修改位置、尺寸或文字时优先使用设计器。表格行高、列宽和缩放参数已经显式设置，按钮区域按内容调整高度，避免设计器保存后变成默认 20 像素行高。整体沿用课堂 demo 的蓝色背景、浅青面板、标准表格与页签。

阅读业务代码时，可以先看 `MainForm.cs` 的识别结果处理，再看 `ManageForm.cs` 的按钮事件，随后看 `AppRepository.cs` 中实际的数据保存与查询。`FaceService.cs` 负责课堂 SDK 接入，沿用课堂流程的地方已标注“沿用课堂demo”。

数据库工具方法按用途命名：`Parameter` 创建 SQL 参数，`QueryTable` 查询数据表，`GetValue` 查询单值，`ExecuteSql` 执行增删改；`QueryForAdmin` 在查询前检查管理员，`RunTransaction` 统一提交管理写入。统计界面只从一份人员快照生成汇总和名单，认证记录只使用一套保存接口。

## 配置与验证

数据库连接统一由 `App.config` 的 `SocialSecurityAuth` 连接串读取，默认为本机默认实例 `.` 和 Windows 身份验证。修改源码配置后重新生成；直接运行发布程序时修改旁边的 `SocialSecurityAuth.exe.config`。

## v1.0.7 操作日志简化（2026-11-03）

之后仅保存注册人员（新建档案或采集注册人脸）、删除人员、清空认证领取记录三类成功操作的日志。管理员登录、普通资料修改、查询及失败操作不再新增日志；失败仍显示错误提示。日志与对应操作在同一事务中保存，失败时一并回滚。数据库表和已有历史日志保留，无需重新建库。

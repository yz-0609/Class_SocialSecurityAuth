核查日期：2026-10-23。本文依据课程任务书、指定 GitHub 仓库源码和本机实际检测整理，未参考目录内其他课题的需求报告。本次未实施业务系统，也未修改已有数据库和课堂 demo 源码。

范围约束：仅实现任务书明确要求的功能，并按用户要求沿用课堂 demo 的人脸识别方法。不将额外业务规则、扩展角色或可选功能纳入开发计划。数据库关联、必要输入校验、识别回调节流及异常处理属于支撑这些功能的技术实现。

## 3. 任务书明确要求

### 3.1 业务目的

针对养老金冒领、盗领以及异地居住人员认证困难，开发基于人脸识别的社保身份认证系统，实现待遇领取资格核验、简化认证流程，并支持认证信息管理与统计。

### 3.2 必须覆盖的功能

| 模块 | 任务书明确要求 | 可验收的结果 |
| --- | --- | --- |
| 管理人员与权限 | 管理人员信息、管理员权限设置 | 能维护管理账户，并限制管理功能的访问 |
| 社保人员管理 | 社保人员信息录入与维护 | 能保存、查询并显示人员档案；档案与人脸关联 |
| 人员注册 | 采集并保存人脸特征 | 注册成功后，该人员能够加入识别人脸库 |
| 自动识别 | 启动后停留在人脸自动识别界面，连续识别 | 无需每次手动点击识别；处理一次后仍能继续识别 |
| 资格认证 | 待遇领取资格认证 | 身份识别结果进入资格核验流程，给出明确结果 |
| 认证及领取记录 | 通过后记录领取信息；失败提示并记录 | 成功、失败均可追溯，成功流程关联领取信息 |
| 操作记录 | 保存操作记录 | 可追查关键管理操作及执行人员 |
| 查询统计 | 按单位查询已采集、已通过、未通过、未认证人员名单；汇总数据 | 单位筛选后可查看相应名单及人数 |

### 3.3 程序展示与课程交付

- 启动时首先显示编写人的班级、学号、姓名和课题名称，停留 2 秒，再进入连续识别主界面。
- 完成需求分析、数据库设计、数据库增删改查与界面设计、人脸模块集成、调试和演示。
- 提交工程压缩包 `project.rar`；清理编译中间文件，保留源码、最终 exe 和数据库文件。实际运行必需的 SDK DLL、音频及配置也应随交付包提供。
- 提交设计报告电子版、打印版和作品演示视频，目录命名为“班级_学号_姓名_课题名称”。
- 设计报告应包括题目描述、设计思路及需求、硬件使用、数据库和系统结构、模块与流程、关键代码、调试问题与解决方式、设计总结及演示方法。

## 4. 按任务书实现的最小流程

### 4.1 人员注册

管理人员录入社保人员信息及所属单位 → 调用课堂 SDK 采集人脸 → 保存人员与人脸特征的关联 → 刷新识别人脸库。

所属单位用于完成任务书要求的按单位查询，具体存储方式在数据库设计时确定。

### 4.2 自动认证

1. 展示课题与作者信息 2 秒。
2. 连接数据库、加载人脸 SDK 和已登记模板，进入连续识别界面。
3. SDK 返回识别结果，识别成功时取得人员编号及档案。
4. 完成基于人脸识别的待遇领取资格认证：通过后记录领取信息，失败时提示并保存失败记录。
5. 返回等待识别状态，继续处理下一次认证。

连续回调的必要节流沿用课堂方法，避免一次识别被反复写入。不增加按月、季度或年度的认证周期及重复领取业务限制，不增加死亡、判刑、失踪状态的独立管理流程。

### 4.3 管理与统计

管理人员按权限操作人员信息、注册及记录查询功能，系统保存操作记录。统计界面按单位提供已采集、已通过认证、认证未通过、未认证人员名单及相应汇总。

统计实现需保持名单与人数一致。“已采集”与认证结果可以交叉；无法确定身份的失败仍保存失败记录，不归入某个已知人员。此类数据关联处理属于查询正确性的实现细节，不新增统计功能。

### 4.4 必需数据

仅围绕管理人员与权限、社保人员及所属单位、人脸特征、认证及领取社保记录、操作记录设计数据库。字段和表结构以支撑任务书功能为限，不预先扩展角色体系、系统参数管理或待遇金额管理。

## 5. 必须沿用的教学人脸技术

源码依据：[frmManage.cs](https://github.com/yz-0609/DoorAccess2026/blob/main/WindowsFormsApplication2/frmManage.cs)；框架与引用依据：[项目文件](https://github.com/yz-0609/DoorAccess2026/blob/main/WindowsFormsApplication2/WindowsFormsApplication2.csproj)。

| 环节 | 教学代码方法 | 课设沿用方式 |
| --- | --- | --- |
| 控件 | `FacePlatformCtrl.BioFPCtrl` | 使用相同 SDK 控件接入摄像头和识别能力 |
| 加载模块 | `ModuleLoad()` | 初始化设备/识别模块，补充返回值与异常检查 |
| 获取特征长度 | `GetFaceCodeLen()` | 按 SDK 特征长度组织模板并校验数据 |
| 加载人脸库 | `SetFaceCode(count, faceCode, Id)` | 数据库读出模板，拼接后传入控件，保存索引到人员编号的映射 |
| 发起注册 | `Enroll()` | 在人员登记界面触发采集 |
| 注册结果 | `EnrollNotify` | 取得 `face_template` 与 `face_image`，保存模板和关联信息 |
| 发起识别 | `Identify()` | 主界面进入连续识别流程 |
| 识别结果 | `IdentifyNotify` | 通过 `face_index` 查回人员，进入社保认证业务 |
| 取消操作 | `Cancel()` | 管理采集/识别之间的切换与停止 |

数据库中的 `FaceCode` 是 SDK 人脸特征数据，不能用普通 JPG 照片替代。新系统可用 `varbinary(max)` 保存模板；课堂 GitHub 映射标为 `Image`，本机课堂数据库实际为 `varbinary(max)`，迁移时应统一映射。

不得自行替换成另一套人脸算法或云端接口；OpenCV DLL 是该 SDK 的依赖文件，不能据此把教学实现描述成自行编写的 OpenCV 人脸识别算法。

GitHub 仓库未包含 SDK 二进制文件和数据库创建脚本；本机已有 DLL 可作为后续联调来源。实际模块加载、运行依赖和释放方法仍需结合开发包文档或联调确认。

## 6. 从课堂 demo 到课设的开发差距

课堂代码已有人员查询、SDK 模块加载、注册模板入库、模板加载、识别回调、语音提示和简单两秒节流，可借鉴其完整人脸调用链。

课设仍需增加或完善：

- 将学生/学号/班级业务替换为社保人员、社保编号和单位。
- 管理人员信息与权限设置，社保人员所属单位信息。
- 主界面自动加载并持续识别，而非仅在管理界面手动触发。
- 认证及领取记录、操作记录、按单位名单查询与汇总统计。
- 注册信息校验、重复登记处理、事务保存、设备和数据库异常提示。
- 模板变更后的识别库刷新与索引一致性。
- 修复课堂代码“卸载”分支仍调用 `ModuleLoad()` 的问题；正确释放接口须以 SDK 为准。
- 统一数据库配置。现有 `App.config`、应用设置及设计器连接分散，不能只修改一处。
- 按任务书整理工程、可执行程序及运行依赖、数据库文件、报告及演示视频。

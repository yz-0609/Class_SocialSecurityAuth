## 编译与数据验证

使用本机 VS2015 MSBuild 14.0，以 .NET Framework 4.5.2、x86 构建。Debug 与 Release 均编译通过。Release 目录具有 exe、配置文件、SDK 托管及原生 DLL、提示音频和建库脚本。

独立 SQL Server 集成测试通过 34 项断言，覆盖：

- 管理账户密码核验、加盐散列、初始化幂等与已有密码保留。
- 人员增改、Unicode 与引号文本、单位关联、模板保存及删除。
- 重复社保编号拦截、无效模板拦截、失败注册的事务回滚。
- 认证通过与失败记录、领取标记一致性、未知失败归属。
- 最近一次认证口径、单位筛选、四类名单人数与明细。
- 越权读写拦截、既有会话权限撤销、最后一个权限管理账户保护。
- 有历史记录人员或账户的关联保护、操作日志。

测试仅使用随机命名的 `SocialSecurityAuth_Test_...` 数据库，结束后已清理。测试中的短字节模板只用于数据库存取测试，没有作为真实人脸模板投入正式程序。正式 `SocialSecurityAuth` 数据库没有预置人员、模板或认证记录。

## v1.0.1 连续注册修复（2026-10-24）

用户反馈连续注册第二人后第一人被覆盖。检查代码与正式库已有操作日志，确认注册完成后编辑器保留了上一次的 PersonId；填写第二人的社保编号时，原有更新逻辑把第一人的资料和模板一并改写。

修复后，注册完成自动清空内部编号、社保编号和姓名，恢复新增状态；选择或保存已有人员后锁定社保编号并提示编辑状态；数据层在事务中核对内部编号对应的原社保编号，发现不一致即拒绝保存，不改变原资料、人脸或单位。

独立数据库测试通过共 46 项断言（原 34 项加 12 项回归断言）。新增回归通过真实管理窗体的注册完成回调验证：

| 操作 | 验证结果 |
| --- | --- |
| 注册第一人后直接填写并注册第二人，不点击新增 | 两人获得不同 PersonId，两份模板均保留，第一人姓名与模板字节不变 |
| 注册完成后检查编辑器 | 内部编号归零，编号与姓名清空，可直接输入下一人 |
| 选择已有人及点击新增 | 已有人员编号只读；新增后解除只读并清除旧编号 |
| 先保存基本资料，再采集人脸 | 人脸保存到同一人员编号，完成后自动回到新增状态 |
| 数据层使用旧内部编号提交另一社保编号 | 拒绝操作；原资料和模板不变，不产生多余单位 |

新增测试未调用摄像头，使用短字节模板验证保存和窗体状态，不代表已完成两位真人的识别准确性验证。测试库已清理；修复和回归没有修改正式库人员、人脸或认证记录。旧版本已覆盖的模板需要用户重新采集。

## v1.0.2 成员删除与领取去重（2026-10-24）

根据用户调整，允许删除已有认证领取记录的成员。删除事务先向历史记录保存社保编号、姓名、单位编号及单位名称，再解除人员关联、删除人脸模板和人员档案，并写入操作日志。历史认证结果、认证时间和领取信息保留，按单位查询继续有效；已删除人员不再进入当前人员统计或人脸模板库。

同一社保编号的领取只登记一次。每次识别成功仍保存认证记录；首次成功同时保存领取标记、时间及领取编号，后续成功仅保存认证结果。主界面分别提示“首次领取已登记”和“已领取，本次不重复登记”。使用 Serializable 事务、人员更新锁及领取编号唯一索引，防止并发产生多条领取登记。删除后使用同一社保编号重新登记，也不会再次产生领取登记。

程序下次启动时自动执行兼容旧数据库的升级：增加历史身份和领取编号字段；旧版重复领取保留最早的一次，其他记录仍保留认证成功结果；更新约束并建立唯一索引。升级幂等，不删除人员、人脸或认证记录，无需重建数据库。

Release v1.0.2 编译通过，共 70 项独立数据库及窗体回归断言通过，覆盖：

| 检查 | 结果 |
| --- | --- |
| 模拟原版数据库和重复领取后升级，重复执行初始化 | 全部认证记录保留，每人仅最早一次为领取登记 |
| 同一人员重复识别成功 | 每次认证成功保留，领取登记仅一次 |
| 8 次并发成功认证 | 8 条认证记录，恰好 1 条领取登记 |
| 绕过数据层直接插入重复领取 | 数据库唯一索引拦截 |
| 有成功及失败认证历史的人员删除 | 删除档案、人脸成功；历史显示内容、时间和单位筛选保持一致 |
| 删除后再次登记同一社保编号 | 新档案编号独立，历史身份不变，领取不重复 |
| 主界面真实认证完成回调 | 首次和再次成功提示正确，两次成功仅一次领取登记 |
| 权限与旧人脸回调 | 无权限删除被拦截；已删除人员不能由旧索引再次认证成功 |

本次测试仅操作随机测试数据库，结束后已清理。未删除正式库成员，也未提前对正式库执行升级。更新程序和 SQL 脚本已生成到 `Build/Release`，版本为 1.0.2.0；未制作新压缩包。摄像头算法未更换，以上回归中的识别回调用于验证业务和界面状态，不是新的真人识别准确率实测。

## v1.0.3 仅首次领取与清空按钮（2026-10-24）

按用户最新要求，认证领取表仅保存每个社保编号首次成功领取的一条记录。重复识别成功直接使用原记录，不新增流水、不改变首次领取时间；失败不写入领取表。人员最新认证时间和结果改为保存在人员表中，继续支持已通过、未通过和未认证统计。

管理界面“认证领取记录”页底部增加“清空认证领取记录”按钮。确认框明确清空所有单位，默认选取消；确认后通过权限核验，在同一事务中重置人员认证状态、删除领取记录并写入操作日志，随后刷新表格和相关统计。人员、人脸模板和管理账户保留。清空后，人员下一次成功可重新登记领取。

数据库升级先提取旧流水中的最新认证状态，再移除重复成功和失败流水，保留最早一次领取及其原始时间。以约束作为升级标记，重复初始化不会恢复已清空记录或改变之后的认证状态。沿用领取编号唯一索引并加上只允许首次成功领取的约束。

新增回归覆盖重复成功不增加行、失败更新状态但不写流水、失败后成功恢复状态、并发成功只保存一行、旧库流水整理、清空权限、跨单位清空、清空后的首次领取和重复初始化。实际窗体截图保存在 `Doc/运行界面/recordsTab_v1.0.3.png`，已检查底部按钮和提示没有遮挡。
